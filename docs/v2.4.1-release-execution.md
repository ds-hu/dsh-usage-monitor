## 5. 发布动作

三趟才发出去，每一次都停在发布之前，registry 上没有留下半成品：

1. 推 `fork-v2.4.1`（`26b8ccd`）→ Test 步失败：`storage.mjs` 的峰谷拆分用例只在 `+08:00` 宿主下成立，
   UTC 下 09 点的桶被算成北京 17 点，`{peak:50, valley:160}` 变成 `{peak:30, valley:180}`。
   修法是在该文件 import 之后把 `process.env.TZ` 钉成 `Asia/Shanghai`（`aa95b5f`），标签重指到该提交。
2. 再推 → Publish 步 `422`：`Error verifying sigstore provenance bundle: package.json "repository.url"`
   指向上游，与 provenance 里的 `ds-hu/dsh-usage-monitor` 不符。把 `repository`／`homepage`／`bugs`
   改到 fork（`24db1eb`），标签再次重指。
3. 再推 → 成功。`dist-tags.latest` 由 2.4.0 移到 2.4.1；可信发布配置因首次成功发布完成校验，
   48 小时过期不再适用。

补充：npm 上先有一个手动发布的 `2.4.0`（gitHead `67250b5`，发布者 `cup113`），用于验证安装路径；
2.4.1 是第一个由 CI 发布的版本。
