# v2.5.0 发布执行记录

新增能力：概览展开行的「Today」换成区间选择器，并在同一行给出各窗口的 token 估算。
`usage.json`（版本 2）、`quota.json`（版本 1）与 `/settings` 契约不变；`/state` 的窗口类限额项多了一个
`estimate{from,to,tokens,dPct}` 字段——2.4.x 的客户端不读它，缺了也不影响渲染。升级不需要迁移。

## 1. 变更范围

| 项 | 位置 | 说明 |
| --- | --- | --- |
| 区间选择器 | `lib/client.js` | 「Today」换成 `[Today ▾]`：切到近 7 天时 token 数、归一比例与五分量条一起换，图表固定 7 天 |
| 窗口估算 | `lib/client.js` | 今日行右侧 `[剩余｜套餐总量]` + 各窗口读数；按斜率折算，悬停给出取样区间、分子分母与 ±1pp 区间 |
| 取样 | `lib/index.js` | `estimateOf`：同一段折线两端之间的 Δpp 与本地小时桶；左端取窗口起点与本地留存边界的较晚者，两端必须落在同一条折线段上 |
| 窗口长度 | `lib/providers.js` | 窗口类条目声明 `windowMs`（OpenCode 5h / 7d / 30d；Command Code 5h / 7d 与订阅周期） |
| 图表标签 | `lib/client.js` | 柱值标签加一层卡片底色，折线从数字背后穿过，不再压花数字 |
| 文案 | `lib/client.js` | 158 → 163 键（`rangeLabel`／`range7d`／`estLeft`／`estTotal`／`estNoData`） |
| 测试 | `test/client.mjs`、`test/runtime.mjs`、`test/copy.mjs` | 客户端补区间切换与估算用例；宿主补 Δpp 取样用例（含留存边界）；文案预算随之上调 |

## 5. 发布动作

一次通过，没有留下半成品：

1. `1e66fb9` = release commit（版本三处同步到 2.5.0、CHANGELOG 补 [2.5.0]、README 补「v2.5.0 更新」）。
2. 打注解标签 `fork-v2.5.0`（说明含行为变更、验证证据、产物校验和与验证边界），推 main、再推标签。
3. `publish` 工作流 31 秒跑完：`npm ci` → `npm test` + `test:pack` → 标签与 manifest 版本核对 →
   `npm publish --access public`，OIDC 换令牌并自动附 provenance。

**registry 有传播延迟**：发布后第一次 `npm view … version` 与直接读 packument 都还返回 2.4.1，
`versions` 里也没有 2.5.0，而 CI 日志已经打出 `+ @ds-hu/dsh-token-quota@2.5.0` 与
`Signed provenance statement`。约一分钟后同一个 packument 才出现 2.5.0、`latest` 也移过去。
判断发布成败要看 CI 日志并稍后复读，不要按第一次读取判失败。

## 6. 验证边界

- 未在真实桌面端 / Web 宿主里安装 npm 包验收。界面本身在用户实机上跑过（区间选择器、估算位置、
  图表标签），但斜率口径的估算是用本地替身宿主（`.scratch/visual`）渲染验证的。
- 估算数值取决于本地留存（默认 7 天）与供应商整数百分比的上报精度：窗口比留存长时，取样只覆盖
  留存那一段，且区间按 Δpp ±1pp 折算——它不是供应商公布的额度。
- 未接真实计费账户；余额、报告费用那条链路本轮没有改动。
