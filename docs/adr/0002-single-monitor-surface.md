# 0002 用量监控收敛为单一面板，明细与统计并入概览的供应商行

状态：已采纳（本次重构起）

## 背景

v2.0–v2.3 期间，界面按功能逐层叠加：侧栏卡片 → 用量浮卡 → 供应商限额明细 → 用量统计弹窗，另有一个含「概览 / 供应商 / 设置」三页签的配置面板。到 v2.3.0，`lib/client.js` 里有四个浮层、八个视图，供应商指标用四种排版重复渲染：

- 浮卡条目：一行主指标 + 状态；
- 明细分栏：每栏一组指标卡；
- 概览卡片：又一组指标卡；
- 统计页：每个供应商一段今日分布与图表。

每个浮层都有自己的打开/关闭、焦点回退、Esc 与数据请求路径；`panelSnapshot` 用 `popover/detail/stats/dialog/page` 五个布尔值维护互斥，调用方必须知道哪些组合合法。文案上，11 处 `.pnote` 常显解释段落和 13 处 `·` 拼接把数据挤到一边。

## 决策

1. **只保留一个浮层**：删除用量浮卡、供应商限额明细弹窗与用量统计弹窗；侧栏卡片单击直接打开「用量监控」面板。
2. **面板只有两个页签**：概览、供应商。卡片进入默认概览；宿主「设置 → 用量监控」进入默认供应商。原「设置」页签并入供应商页底部的折叠「全局设置」。
3. **概览用可展开的供应商行**：折叠行只给名称、状态、主指标与今日量；一次只展开一行。展开区放指标表格、今日五分量分布与比例、DeepSeek 的计费时段拆分、按需取用的额度历史图，以及「配置」入口。
4. **文案默认不解释**：说明移入收起的 `InfoHint`（`<details>`）；缺次年节假日、保存失败、取数失败等会改变判断的告警保持可见。
5. **额度历史按需取一次**：首次展开供应商时请求 `/state?quota=1`，同一面板会话内复用；不再为打开统计弹窗单独请求。

## 理由

- **删除测试通过**：删掉浮卡、明细、统计三个浮层后，它们的独有内容（比例、图表、历史）并入概览的同一行；但“打开哪个界面、焦点回到哪里、Esc 关闭谁”这层复杂度直接消失，而不是转移到别的调用方。供应商指标的四种排版收敛为「行摘要 + 指标表格」两处。
- **导航深度下降**：卡片 → 某供应商完整指标/图表由 3–4 次点击降到 2 次；卡片 → 供应商配置由 4 次降到 3 次。
- **文案密度可度量**：默认视图不再有 `.pnote`；`·` 拼接改为表格、badge 或 `InfoHint`；词典从 198 键降到 158 键。
- **无构建约束不变**：`lib/client.js` 仍是手写单文件，不引入打包步骤；深度来自文件内部的 surface store、`PanelHost`、panel controller 与 `metricRowsOf`，不是文件拆分。

## 后果

- 失去浮卡的非模态速览：卡片本身承担速览，完整信息一次点击进入面板。
- 移动端不再有「直达详情」分支：宽窄布局都打开同一面板，`useMobileLayout` 与相关测试删除。
- 测试入口整体改写：浮卡定位、统计弹窗、明细分栏的用例替换为「单一面板 / 手风琴行 / 指标表格」；草稿身份、保存锁、焦点、轮询、会话隔离、峰谷与关注限额的行为断言保留。
- 面板在窄视口下只滚动自身，指标表格在行内横向滚动，不产生页面级横向滚动。

## 被否决的替代方案

- **保留浮卡，只合并详情与统计**：仍有三层浮层和两套供应商排版，最花时间的「浮卡 → 详情 → 统计」链路没有变化。
- **单面板但保留三页签**：设置与供应商仍是兄弟页，「设置 → 供应商」的两步导航保留，概览与供应商的指标排版继续重复。
- **拆文件或引入构建步骤**：浏览器端只加载 `exports["./client"]` 的单个 factory；拆文件需要先引入打包与 chunk 加载，与 ADR-0001 记录的「手写无构建」约束冲突，收益低于本轮界面收敛。
