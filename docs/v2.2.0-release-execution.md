# v2.2.0 发布执行记录

本轮把自 `fork-v2.1.0`（`4411178`）以来未发布的五批改动一并发布：**密钥改存凭据引用**（`a62b00a`）、
**窄布局点击直达详情**（`3a13130`）、**Plugins 面板名称与图标**（`78800e2`）、**关注限额**（`0dfce25`）
与**用量分布、额度历史与统计图**（`cad5dc0`）。五者叠加是新增能力，因此递增次版本号到 **2.2.0**。

语义化依据：新增统计弹窗、额度历史采集、关注限额、凭据引用与两处入口变化，均无破坏性变更。
唯一的单向变化是 `usage.json` 升到**版本 2**：旧版插件读到版本 2 会判为不支持并原样保留文件
（不丢数据、也不回写），因此本轮不是补丁号。版本 1 文件读取时自动兼容，无需迁移。

## 1. 变更范围

| 能力 | 实现位置 | 说明 |
| --- | --- | --- |
| 用量五分量 | `lib/usage.js` 取值 + `lib/storage.js` `USAGE_COMPONENTS` | 未缓存输入／输出／缓存命中／缓存写入／未细分，四项之和即总量；分量互不相交，不重复计数 |
| 用量文件版本 2 | `lib/storage.js` `loadUsage` / `saveUsage` | 版本 1 的总数归入「未细分」；未知版本不读也不覆盖；`llm/retry-started` 结束替换范围 |
| 额度历史采集 | `lib/quota-history.js` + `lib/scheduler.js` 的 `onSample` | 查询成功后按「供应商 × 指标」记录已用百分比的变化点，不变的值不重复记；磁盘 14 天、每指标 600 点 |
| 跨进程合并 | `lib/quota-history.js` `mergeQuota` / `acquireQuotaStore` | 按时刻并集合并（重复合并不翻倍），与用量文件同目录、共用一次防抖落盘与短写锁 |
| 历史按需下发 | `lib/index.js` `readQuotaQuery` / `buildStatePayload({ quota })` | 只有 `/state?quota=1` 带历史：先裁剪到展示窗口，再降采样到 ≤120 点；常驻轮询不带 |
| 统计弹窗 | `lib/client.js` `StatsModal` / `UsageChart` | 柱=每日 Token 消耗（左轴，刻度为最高那日），线=各窗口剩余额度（右轴 0–100%），共用时间轴与日期刻度；额度回落处断线 |
| 比例与分布条 | `lib/client.js` `ratioPartsOf` / `fmtRatioPart` / `usageRatioOf` | 「缓存命中 : 缓存未命中 : 输出」归一为未命中 = 1，三段各 3 位有效数字；分布条只画这三段 |
| 关注限额 | `lib/client.js` `selectBarMetrics` + 设置页 `displayKeys` | 勾选顺序即排列顺序，↑↓ 调序；交集为空回落默认规则（周窗口 → 最紧窗口 → 文字），绝不画 0% 假条 |
| 稳定窗口标识 | `lib/providers.js` 条目的 `key` / `short` | 窗口识别不再只靠名字里的「周」；已勾选但未返回的项标注「当前不可用」 |
| 凭据引用 | `lib/detect.js` 补丁 + `lib/index.js` 解析 | 只写 `apiKeyEnv`（凭据库记录名或环境变量名），密钥本体不落 profile；旧 `apiKey` 仍按「本体优先」生效 |
| 窄布局直达详情 | `lib/client.js` `MOBILE_LAYOUT_QUERY` | 视口 < 1024px 一次点击直接开详情，桌面宽布局仍走浮卡 |
| Plugins 元信息 | `icon.svg`、`locale/{zh,en}.json`、`package.json` exports | 卡片与详情显示「用量监控 / Usage monitor」，不再是裸包名与占位图 |

### 基准（本轮现场生成）

`node scripts/benchmark-storage.mjs`：

| 场景 | 体积 | 保存 p50 / p95 | 今日统计 vs 旧式遍历 |
| --- | --- | --- | --- |
| 1 供应商 / 7 天 | 15,224 B | 12.309 ms / 18.207 ms | 5.297 µs vs 15.423 µs（2.9×） |
| 1 供应商 / 90 天 | 194,504 B | 25.38 ms / 88.095 ms | 5.295 µs vs 468.931 µs（88.6×） |
| 13 供应商 / 7 天 | 196,979 B | 33.757 ms / 41.572 ms | 16.305 µs vs 50.99 µs（3.1×） |
| 13 供应商 / 90 天 | 2,527,619 B | 263.957 ms / 280.543 ms | 17.9 µs vs 956.841 µs（53.5×） |

体积与保存耗时相对 v2.1.0 明显上升（同一场景 1 供应商 / 7 天由 4,640 B 增至 15,224 B，13 供应商 /
90 天由 758,579 B 增至 2,527,619 B）：小时桶从「一个总数」变成五项分量对象，这是分布比例与统计图
的**直接代价**，不是实现缺陷。默认保留期 7 天时单供应商约 15 KB；把保留期拉到 90 天且挂多个供应商，
才有上面 2.5 MB / 264 ms 的量级，而落盘本身是防抖后的异步写，不阻塞 `/state`。

`node scripts/benchmark-runtime.mjs`：`/state` 响应 p50 **0.273–0.810 ms**、p99 ≤ **1.839 ms**
（1–20 客户端 × 0–100 事件/秒），事件循环 p95 11.56–12.09 ms，RSS 稳定在 68.7–77.7 MB，
查询并发峰值 0，5 轮挂载／卸载后句柄 2 → 2。两者均为本机合成负载，不代表真实服务器、真实账户或
真实浏览器延迟。

### 产物复测（不「只测源码」）

把 `dsh-token-quota-2.2.0.tgz` 解包到工作区内的独立目录后实测：

| 命令 | 结果 |
| --- | --- |
| `npm install --ignore-scripts` | 15 个包安装成功 |
| 逐个 `node --test-reporter=tap test/*.mjs` | **120 项全部通过**（另 8 个自带断言脚本以 ✓ 行输出、退出码 0，共 25 个文件） |
| `npm run test:pack` | 通过：58 个文件、256,232 字节（与产物一致） |

解包目录里直接 `npm test`（`node --test test/*.mjs`）会因受限沙箱拒绝测试运行器派生子进程而
`EPERM`，因此改为逐文件直接跑：同一批用例，只是不交给运行器派生子进程。

逐字节同一性：解包目录与仓库工作区相比，`lib/` 下 12 个运行时模块与 `test/` 下 28 个测试文件
（含 3 个浏览器用例）**全部 SHA256 相同**（无缺失、无多余），因此第 3 节那 32 项浏览器断言针对的
就是产物里的这份客户端字节。

## 6. 验证边界（**未执行项**）

- **未跑真实宿主验收**：`npm run test:desktop`、`scripts/verify-web.mjs`、`npm run test:lifecycle`
  均需 Windows 桌面端可执行路径，本轮未执行，因此「真实 Desktop／Web 安装、原生设置入口、侧栏
  收起恢复」仍沿用 v2.0.4 的结论。

  本轮**不引入价目表**，因此不计算金额。
- **额度历史没有回填**：折线从插件开始运行的那天起累积，安装前的历史补不回来。磁盘保留 14 天，
  界面展示窗口取 `min(7, retentionDays)`，刚用几天时线会偏短。
- **产物侧的浏览器套件未实跑**：受限沙箱拒绝 Playwright 派生浏览器进程（`spawn EPERM`），32 项
  浏览器用例是在仓库工作区跑的；产物侧改用 `lib/` 与 `test/` 逐字节同一性证明（见第 5 节）。
- **未创建 GitHub Release**：与前几轮一致，发布只体现为注解标签 `fork-v2.2.0` 与推送；不推上游
  `shxtmaker/dsh-token-quota`。
- **统计弹窗的人眼复核**：见第 4 节。
