# 运行时可靠性与交互改进

v2.2.0 发布自 v2.1.0 以来未发布的五批改动：用量分布与额度历史（`usage.json` 升到版本 2、`quota.json` 按需传输、统计弹窗柱线合图）、关注限额（卡片多条进度条）、凭据引用取代密钥本体、手机／窄布局直达详情、Plugins 面板元信息。实现、验证与边界见 [v2.2.0 发布执行记录](v2.2.0-release-execution.md)。

v2.1.0 发布自 v2.0.5 以来未发布的两批改动：DeepSeek 峰谷计费时段（宿主判定、客户端只消费结论、按小时桶纯读拆分今日用量、设置页节假日覆盖表）与常驻卡片重新排版（周窗口进度条取代阈值圆点与模型名、Token 量级统一 3 位有效数字、浮卡去重）。实现、验证与边界见 [v2.1.0 发布执行记录](v2.1.0-release-execution.md)。

v2.0.5 修复智谱／Z.ai Coding Plan 查询失效：用量窗口改由 `unit` 标识分类（供应商已把 `TOKENS_LIMIT` 改名为 `CREDIT_LIMIT`），并新增周窗口与供应商公布的重置时刻；业务失败改按响应信封判定，密钥失效归 `auth` 而不是解析错误。实现、回归与验证边界见 [Coding Plan 窗口修复执行记录](zai-credit-limit-fix-execution.md)。

v2.0.4 统一重置时刻与日期文案的有效性判断，未知占位不会回退成日历日期；客户端与数据层共同拒绝误传入毫秒字段的秒级值。实现与回归记录见 [重置时间修复执行记录](reset-time-fix-execution.md)。

v2.0.3 的侧栏浮卡复用现有数据控制器和手动刷新合并机制，不增加独立轮询。浮卡与详情、设置入口互斥，卸载时释放窗口、焦点和外部点击监听。实现与验证边界见 [侧栏用量浮卡执行记录](usage-popover-execution.md)。下文保留原 R1–R6 实施说明。

## 实现范围

保留现有供应商注册表、凭据类别隔离、HTTP 查询保护、DSH 官方槽位、版本 1 小时桶格式与无构建客户端加载方式。
改动集中在异步状态一致性、扫描提交边界与低成本热路径。

| 范围 | 最终行为 |
| --- | --- |
| 请求生命周期 | 后台 `GET /state` 改为「完成后调度」：上一次结束（或失败退避）后再排下一次，不再固定间隔并发发起。同一会话同时最多一个后台 GET，重复 load 合并，切页取消旧请求并立即查询新会话。 |
| 取消与超时 | `AbortController` 负责释放请求，「在途令牌 + 请求代次」负责阻止不可取消/已完成请求回写；两者不可互相替代。GET 初始等待上限 30s；refresh/test 为后端 120s 查询留出 130s+ 余量；settings/rescan 30s。 |
| 失败退避 | 取数失败按 10→20→40→60s 退避，成功后复位 10s；会话切换/隐藏/卸载导致的取消不计为失败。 |
| 页面可见性 | 隐藏时停止后台定时器并取消在途 GET；恢复可见时只启动一次查询，不叠加恢复与定时两路请求。 |
| 手动刷新 | 刷新开始时暂停后台轮询并取消旧 GET，重复点击合并为一次；完成后发布结果并恢复轮询。连接断开不代表服务端操作被撤销。 |
| 编辑器身份 | 每次打开供应商创建新的 `editorId`；保存、连接测试绑定 `editorId` + 草稿修订号 + 操作序号。返回目录或切换编辑器立即取消本地回写资格，已发出的保存仍可能成功，重新打开以服务端为准。 |
| 目录刷新 | 目录请求带序号，旧响应不得覆盖新响应；刷新目录不重新初始化已有草稿。 |
| 阈值判定 | 详情卡、供应商状态药丸、设置页预览与状态标记共用 `classifyPct(pct, { warnPct, critPct })`（默认 80/95）；无值/未知值/NaN 归为 unknown，不折成正常的 0%。 |
| 扫描协调 | 新增 `lib/scan-coordinator.js`：目标版本 / 完成版本 / 单实例并发 / 追赶一轮。周期触发复用进行中的扫描；来源变化（路由/凭据/配置）版本 +1 使旧候选失效；提交前同步校验版本。 |
| 手动重扫 | 等待覆盖「本次点击版本」的新扫描；30s 拿不到就返回失败 +「稍后重试」，不把点击前的扫描包装成成功。 |
| 设置写入 | 自动填入与 `/settings` 共用插件内部串行队列，任务执行时读最新配置；空秘密字段不覆盖，已有密钥不自动覆盖。 |
| 自身写入识别 | `settings.watch` 区分自动填入自身写入与外部变化：自身写入不推进版本（避免与扫描互相触发），外部变化才使旧候选失效。 |
| 当前发现 | `added = 当前发现 ∨ 已启用 ∨ 任一密钥已填`；`autoDetected` 统一表示「当前发现」，历史来源继续用 `autoSource` 展示。扫描失败保留上次成功发现并以 `detect.error` 标明未刷新；一次成功的空扫描才移除当前发现。 |
| 今日统计与历史 | `sumDayTokens` / `scanDay` 只读当天 24 个本地小时键；近 N 天历史（`dayUsageHistory`）每天 24 键、最多 7×24，按本地日历日回退。自然日边界每轮状态生成只捕获一次。不新增缓存或午夜定时器。 |
| 用量记账 | recorder 返回「桶是否真的变化」；同一 (session, turn, step) 的五项分量全等时不触发 `markDirty`/落盘。`llm/retry-started` 结束替换范围，重试尝试累加。保留期变化引起的保存独立生效。 |
| 官方地址策略 | `OFFICIAL_ENDPOINTS` 成为主机/基础路径的唯一事实来源，查询函数与探测校验共同引用，声明位置不再依赖注册表求值顺序。 |
| 用量目录迁移 | 目标目录必须不存在才 rename（Windows 的 rename 在目标已存在时直接失败）；目标为空目录或缺 `usage.json` 时回落旧路径读取，不合并、不覆盖；EXDEV/EPERM/占用失败保留旧数据并可诊断。 |
| 额度历史采样 | 只在查询**成功**时采样（失败保留的旧数据不是「现在的额度」）；`onSample` 抛错就地吞掉，不影响调度与卡片。只接受带安全 `key` 且 pct 在 0–100 的条目，`null`／`""`／非数字一律视为「没有值」（`Number(null) === 0` 会把余额记成 0% 假点）；`constructor` 等原型链键单独挡掉。 |
| 额度历史读取 | 仅 `?quota=1` 回传；按用量展示窗口裁剪（左缘多留一个切点前的锚点），再降采样到 ≤120 点（每段保留首尾，重置落差不会被抹平）。没有采样点的供应商不挂该字段，客户端据此决定要不要画折线。 |

## 存储设计

继续使用同一路径的小时桶文件，版本 2。小时桶值是稀疏分量对象（未缓存输入／输出／缓存命中／缓存写入／未细分），四项分量按 DSH `TokenUsage` 的互不相交口径记账；版本 1 的数字总量在读取时归一为 `unsplitTokens`，不猜分布、不丢总量，下一次真正落盘时写成版本 2。旧版插件读到版本 2 会判为不支持并保留原文件，不会覆盖。

相同路径的进程内实例共享存储；跨进程写入先获取短写锁，读取最新文件，再把当前实例相对上次成功保存的增量按**分量**合并进去。不会全量覆盖另一个写者的新增用量，也不会把公共历史基线重复相加；两个进程各写不同分量时都保留。

没有新事件且保留期未变时不执行空闲保存；写入成功才推进基线，失败保留内存增量并退避重试。退出冲刷最多等待短写锁两秒。读取损坏或版本不支持的文件时保留原文件并上报错误，修复后可重试；替换失败会清理本次临时文件。

额度历史是同一目录下的 `quota.json`（版本 1），与用量文件共用一次防抖落盘（一个计时器、一次冲刷，避免两个文件在进程退出时各自漏写）。它的合并是**按时刻取并集**而非基线差值：同一份本地数据重复合并结果不变，因此不需要 baseline；跨进程仍走同一把短写锁，读最新文件后合并再原子替换。磁盘保留固定 14 天、每指标上限 600 点，与可配置的用量保留期解耦——展示窗口在读取侧裁剪，磁盘上的余量留给窗口变宽时使用。额度文件损坏或版本不符时按「无历史」处理并保留原文件：这一路失败只影响折线，绝不影响卡片与今日用量。

本轮只升级本地用量文件（版本 2）；不迁移 settings 命名空间、不引入数据库。异步持久化专项仍未启动，启动条件与最小设计见 `docs/refactoring-plan.md` 第 6 节。

## 验证

完整证据、命令与数值见 `docs/validation-report.md`。要点：

- `npm test`：57 个顶层测试项全部通过（新增扫描协调、请求生命周期、用量去重、时区/迁移与地址集合用例）。
- `npm run test:browser`：6 个 Chromium 测试通过，覆盖草稿保留与编辑器身份、旧测试结果不回写、阈值一致性、键盘焦点与 390px 窄屏详情。
- `npm run test:pack`：39 个文件、约 152 KB；`lib/scan-coordinator.js` 等运行时模块已加入必需文件断言。
- 全部 `lib/*.js` 语法检查与 `git diff --check` 通过。
- 存储基准（13 供应商 / 90 天）：完整同步保存 p50 约 37 ms；今日统计由「遍历 2160 桶」变为最多 24 次键查询，实测约 93×。
- 运行时基准：单客户端下 `/state` p50 < 1 ms、事件循环 p95 < 2 ms；空闲且配置未变时用量文件零重写。

## 验证边界

- 供应商响应测试均使用替身数据，未访问真实计费账户；基准脚本也使用固定响应。
- 本机为 Linux（Node 22）：Windows 路径语义（rename 目标已存在即失败、EXDEV/EPERM）通过 `syncBuiltinESMExports` 注入的错误码与真实临时目录覆盖，未在 Windows 主机上运行。
- 未在真实 DSH 实例中做端到端验收；真实宿主接入不等于真实计费接口已验证。
- 跨重启事件重放去重仍依赖宿主稳定事件标识；文件系统持续拒绝写入或异常退出时，尚未持久化的增量仍可能丢失。
