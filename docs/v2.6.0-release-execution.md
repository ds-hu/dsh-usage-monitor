# v2.6.0 发布执行记录

自 v2.5.0（2026-11-03）以来的一批改动，主题是**任意供应商的 token 统计**：DSH 里未归属到内置供应商的路由，
此前被整段丢弃；现在它会成为一条「仅计量」供应商行，同时把「今日总量」的口径从「当前供应商之和」改成
「概览列表里每一行之和」。

行为变更逐条见 [CHANGELOG](../CHANGELOG.md)，术语定义见 [CONTEXT](../CONTEXT.md)，用户文档见
[README](../README.md) 与 [README.en](../README.en.md)。

## 1. 变更摘要

| 面 | 变更 |
| --- | --- |
| 账本归属 | 新增 `lib/ledger.js`：一条 route → 一个账本 key（注册表 id ｜ `local:<route>`），纯函数、只看 route |
| 未识别路由 | 不再丢弃；按 `local:<route>` 落账，出现在概览里，可改名、不可增删停用 |
| DeepSeek | `deepseek-account` 显式并表进 `deepseek`，同一账户一行；登录态的 token 不再丢失 |
| 今日总量 | 概览列表里每一行之和；`added` 增加「今日有用量」这一项 |
| 收编 | 路由后来被注册表认领时，历史桶并入正式供应商，且记录器的扣减跟着搬家走 |
| 文案 | 净增 4 键（163 → 167），区间选项并入既有的 `statsWindow` |

两条守卫做过反向验证，确认断言不是空的：

- **收编后的重复计入**：把 `bucketIdOf` 的扣减退回 `buckets[previous.supplier]`，`test/metered.mjs` 立刻红
  （`1200 !== 600`）；恢复后文件 sha256 与改前逐字节一致。
- **今日总量口径**：`test/client.mjs` 的侧边栏用例把一条 `current: false` 但 `todayTokens` 非 0 的行计入合计，
  改回旧口径即失败。

真实宿主验收（人工，用户在 `web` profile 上执行；宿主进程在代码写入之后重启）：

- 概览出现「仅计量」行（`local:phoebe-southwood`，显示名 PS API），今日与近 7 天同量级，无进度条、
  无指标表、无「数据时间」，动作按钮为「改名」；
- 今日总量等于列表各行今日数之和；
- 继续对话后该行与总量一起增长；
- 供应商页该行没有启用开关，编辑页只有名称与 DSH 路由。

## 3. 验证边界（未执行项）

- **未在 Windows 桌面端（desktop profile）跑安装与界面验收**：本轮只验证了 `web` profile 的真实宿主。
- **收编路径只测了模拟扫描**：`test/metered.mjs` 用 `foreign` 配置触发一次真实的重扫，但没有在真实 DSH 里
  制造「路由中途被认领」的拓扑变化。
- **`meteredNames` 的坏形状只在单测里验证**：`z.dict(z.string())` 遇到非字符串值会让整份配置解析抛错，
  宿主侧 `readConfig` 会把它吞成 `{}`（所有供应商配置一起消失）。这条与既有的 `holidays` 同源，本轮未改。
- **保留期 < 7 天时的窗口标签只做了组件测试**：真实界面按 `poll.usageHistoryDays` 渲染，未在桌面端复核。
- **`/settings` 的 `meteredNames` 上限 200 条**：超出部分静默丢弃，实际不可达，未测。
- **未接任何真实第三方供应商的额度接口**做交叉核对（「仅计量」行本来就没有额度可查）。

## 4. 兼容性

- `usage.json` 仍为 `version: 2`，桶结构未变；`local:<route>` 只是新增的 key，旧版本读到时按「不认识的供应商」
  忽略，不会覆盖原文件。
- 配置新增 `meteredNames`（route → 名字，默认 `{}`）。旧配置缺少该键时按空对象回退，无需迁移。
- 从 2.5.0 升级不需要卸载重装：`dsh plugin --profile <p> add @ds-hu/dsh-token-quota` 覆盖安装后重启 DSH。
