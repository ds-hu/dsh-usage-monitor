# 用量分布、额度历史与统计图

## 实现范围

本轮回答两个问题：今日 Token 到底花在哪儿（缓存命中、未缓存输入、输出各占多少），以及各窗口的**剩余额度**随时间怎么变化。两者都在新开的「用量统计」弹窗里，用一张图呈现。

### 用量分布

DSH 的 `TokenUsage` 是**互不相交**口径：`inputTokens` 只算未命中缓存的部分，`cacheReadTokens`／`cacheWriteTokens` 单列，`totalTokens` 是四项之和。因此本地小时桶从「一个总数」升级为五项分量（未缓存输入／输出／缓存命中／缓存写入／未细分），`usage.json` 版本升到 2。版本 1 的数字总量在读取时归入 `unsplitTokens`，不猜分布、不丢总量；下一次真正落盘写成版本 2。旧版插件读到版本 2 判为不支持并保留原文件。

同一份数据在界面上有三处呈现：详情栏的今日行给「总量 + 三段分布条 + 归一比例」，统计页给五项图例与比例，卡片标题行只给今日总量。

归一比例把前三项除到「未命中 = 1」，例：`30.0 : 1.00 : 0.150`。三段各保留 3 位有效数字，与卡片上的量级口径一致；两侧量级常差两个数量级，位数不统一就无法竖着比。未命中为 0 时改按三者中的最大者归一（不除零）；三分量全 0 时不给比例。未细分不进比例——它没有分量信息，塞进任何一段都会撒谎。

### 额度历史

额度只能在「查询发生的那一刻」被看到，插件此前只保留最新一份快照（重启即丢），因此无法回答「这个窗口什么时候开始烧、还剩多少」。新增 `$DSH_HOME/dsh-token-quota/quota.json`（版本 1），按「供应商 × 指标」记录**已用百分比的变化点**。

三个设计选择：

- **记 pct 而不是记剩余、也不记 resetAt**：剩余 = `100 − pct` 是纯派生；而「窗口内额度只增不减」这条不变量本身就是重置的证据——pct 变小即换了新窗口，折线在此断开，无需额外字段。
- **变化采样**：值没变就不写。额度在窗口内单调，重复点只占体积不增加信息，一次 5 小时窗口通常只有几十个变化点。
- **传输与存储分离**：磁盘固定保留 14 天、每指标上限 600 点；回传时裁剪到用量历史的同一窗口（默认 7 天）并降采样到 ≤120 点，且只在 `?quota=1` 时返回——常驻卡片一直在轮询，把整个窗口的采样点塞进每次响应是纯浪费。

合并是**按时刻取并集**，幂等，因此不需要用量存储那套 baseline 差值；跨进程仍走同一把短写锁（读最新 → 合并 → 原子替换）。两个文件共用一次防抖冲刷，避免进程退出时各自漏写。

### 统计图

一张图两套量纲：柱是每日 Token 消耗（左轴，顶端刻度为最高那日），折线是各窗口剩余额度（0–100%），共用一条时间轴与日期刻度。柱按自然日占位，今天那根只画到此刻；折线在 pct 回落处断开，不把两个窗口连成一条斜线。图例直接写 `5h 剩余 37%`，既是图例也是当前值，省掉独立的数值行。

刻度是 HTML、折线是 SVG：`preserveAspectRatio="none"` 让 SVG 铺满容器，但会把文字横向拉扁，所以日期刻度用百分比定位的 HTML 元素，并按 `padL/padR` 换算回同一坐标系；折线加 `vector-effect="non-scaling-stroke"` 保持线宽不被拉扁。

没有额度历史时只画柱，不画空折线，也不显示空图例。统计弹窗的供应商数据取自常驻 `/state`，额度折线在打开时按 `?quota=1` 另取一次；刷新按钮同时刷两者。

## 验证结果

| 检查 | 结果 |
| --- | --- |
| 单元与集成（逐文件 `node test/*.mjs`） | 25 个文件全部通过 |
| `test/quota-history.mjs` | 采样边界、原型链键、合并幂等、保留期修剪、降采样保首尾、存储/锁/损坏文件 |
| `test/runtime.mjs` | `?quota=1` 才回传、裁剪到用量窗口、成功查询追加采样且同值不重复、dispose 后落盘 |
| `test/client.mjs` | 比例归一与边界、今日行两行版式、合并图柱/线数量与刻度对齐、无历史时只画柱 |
| `npm run test:browser` | 32/32 通过，含新增统计页用例（柱数、折线段数、图例、刻度与柱居中对齐、无横向溢出、Escape 后焦点回到标题行） |

回归中修掉的实际缺陷：`Number(null) === 0` 会把余额条目记成 0% 假点；`constructor` 通过字符集校验后命中原型链；今日行分布条画五段而数字只给三段（多出一个无解释的灰色尾巴）；日期刻度忽略 viewBox 内边距、整体偏移约 15px；今天那根柱只画半格导致刻度偏半格。

## 验证边界

- 额度折线依赖插件运行期间的采样，装插件之前的历史无法补录；期间没有查询就没有点。
- 只对带百分比的窗口成立。余额与报告费用没有百分比，不进折线。
- 供应商响应均使用替身数据，未访问真实计费账户；浏览器用例的额度历史是预置夹具，不是真实采样结果。
- 本地用量统计与供应商账单可能因周期、时区和统计范围不同而不同。

## 后续修订：折线可读性

2.2.0 的第一版在真实数据下暴露三个问题：采样点只有四个时折线是几块孤立的色块、换窗口处的空档像「画漏了」、图上没有任何数字。

- **锚点**：每个变化点画一个圆点。叠加层单开一个不带 `viewBox` 的 SVG（位置用百分比、半径用像素），点才是正圆——原先 `circle` 放在 `preserveAspectRatio="none"` 的画布里，面板一宽就被拉成椭圆，一窄就缩成一像素。
- **换窗口的虚线**：两段之间用同色虚线接上。实线仍然断开（不把两个窗口连成一条斜线），但读者看到的是「这里掉下去了」而不是「线画断了」，也不必猜断点是不是渲染 bug。
- **悬停读数**：指针在图上移动（或聚焦后用 ←/→）时落一条十字线，浮层给出那一刻的时刻、当日 Token 与各窗口剩余百分比。读数取该时刻之前最近一次采样并保持到下一次变化（`quotaUsedAt`），不插值——插值会造出从未采样到的数字。靠近采样点会吸附过去，读数因此停在实际的采样时刻；触屏点一下即固定读数。

验证：`test/client.mjs` 增补锚点/虚线数量、悬停浮层与 `quotaUsedAt`/`clockOf` 的边界；`test/browser/interactions.spec.mjs` 增补悬停可见性、十字线、锚点数与移开收起。
